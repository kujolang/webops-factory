# Set up WebOps Factory for an owner

Clone the repository and follow the README commands. Run the doctor before starting work. Ask the owner to complete Codex login when account authentication is unavailable; never ask them to paste credentials into a mission or commit authentication files.

Identify the site's static export directory and the owner's objective. Read its public-facing copy, then create a mission with title, site and objective. Keep the objective about the four supported checks. Do not alter the controller to accommodate a normal website idea. If the site requires JavaScript, a framework build, backend execution or authenticated pages, explain that this release does not support it.

Run a fixture rehearsal on the included example if you need to check installation without model usage. Then run the owner's mission with --live. The command authorizes draft candidate repairs, not production changes. Open the floor on port 4383 and inspect the repairs and evidence.

Verify the package, explain remaining crawl warnings and give the owner the patch and candidate path. A blocked run is a real outcome: inspect its receipts and revise the mission or input before starting another run. Do not fabricate a passing review, suppress browser errors or substitute fixture results for live evidence.

Only copy reviewed changes into the owner's repository through their normal approval process. This factory does not deploy. Keep private run artifacts and account state out of public demonstrations.
